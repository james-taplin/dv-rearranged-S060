This fixture executes the actual `WheelRearranger.Additional.cs` partial and `PoweredWheelRotater.cs` with minimal Unity hierarchy/transform stand-ins. Run `Validate.AdditionalArrangements.ps1` from the repository; it records source SHA256 values in a timestamped `build/additional-arrangements-validation/run-*/validation.json` report. It does not build or install the game mod.

The source-wheel fixtures deliberately carry colliders and rigidbodies, while the production presentation objects must acquire neither. Fixtures also preserve all six oil-provider ancestries, use rotated car/bogie frames, and begin with legacy scaled/offset drivetrain roots. Assertions cover the visible wheel target, sole retained native axle, dense spark index, inherited-scale removal, native rotation copying, same-object resizing, repeated suspension/restoration/disposal, conventional axle alignment, and second-car isolation.

The restoration fixture is an independent snapshot of the native objects, rather than the production `GeometryState`; the caller is reviewed separately to confirm suspension precedes both prepared and stock restoration, and that snapshots restore native `PoweredWheel.wheelTransform`. Repeated per-transform and renderer assertions account for most of the check count.

This cannot establish Unity Animator curve behavior, actual rendering/LOD, native collision clearance, oilcup interaction, physics performance, or in-game switch/pool acceptance. `setWheelRadius` is an observable stand-in, and native physics state has its separate fixture. The selected tread diameter differs from the outer mesh/flange bounds, just as the native S282 wheel mesh radius differs from its native physics tread radius.
